=== CHECKPOINT 4: file ops layer implemented (2026-08-11) ===
Implemented the file-operations core for Linux, mirroring the reference
Windows file_ops.c/copy_progress.c semantics:
  - file_ops.c: exists (stat); copy/copy_with_progress (64KB buffered loop,
    progress callback fires per chunk; overwrite policy enforced);
    move = rename() first, EXDEV fallback = copy+delete;
    copy_directory/move_directory = recursive copy; move merges into an
    existing destination dir, else rename, else cross-device copy+delete;
    recycle = freedesktop.org Trash spec ($XDG_DATA_HOME/Trash or
    ~/.local/share/Trash, files/ + info/ .trashinfo with DeletionDate);
    delete_permanently = recursive delete;
    delete_disposition = PERMANENT when path is under /media/, /run/media/,
    or /mnt/ (removable heuristic), else RECYCLE;
    delete_disposition_for_drive_type(REMOVABLE)=PERMANENT else RECYCLE;
    delete_flags: RECYCLE->ALLOW_RECOVER, PERMANENT->CONFIRM.
  - file_ops.h: added FILE_OPS_DRIVE_TYPE_* (matches Windows DRIVE_ values)
    and FILE_OPS_DELETE_FLAG_* constants.
  - copy_progress.c: copy_progress_should_show mirrors reference (600ms rule);
    copy_progress_copy does a synchronous GTK-free copy (progress dialog is a
    future app.c GUI-layer enhancement; core stays GTK-free).
  - tests/test_file_ops.c mirrors reference file_ops_smoke.c: delete policy,
    collision/overwrite rules, progress callback totals, nested dir copy+move,
    trash round-trip, permanent delete. Passes.
Build: clean (zero warnings), 5/5 ctest green, audiocommander still launches
under Xvfb.
